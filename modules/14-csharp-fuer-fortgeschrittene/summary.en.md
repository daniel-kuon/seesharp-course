# C# for Advanced Users: Null Safety, Pattern Matching, Span

Chapter 15 (page 949) collects language features that help you catch errors early and keep code short and fast: the compiler tracks `null`, patterns replace chains of branches, and spans avoid copies.

## Null Safety (15.1, pages 949–971)

When **the nullable context** is enabled (`<Nullable>enable</Nullable>`), a reference type is considered non-null: `string` cannot hold `null`, whereas `string?` can (15.1.1). There is no difference at runtime; the annotation is information for the compiler. **Null-state analysis** tracks whether each expression is “maybe null” or “not null” and issues warnings when null is assigned to a non-nullable variable or when a possibly null value is dereferenced (15.1.2, page 953). Warnings are resolved through code: check, use `?` types, or model the code differently. The **null-forgiving operator** `!` (the book's "null-Toleranzoperator", 15.1.2.2, page 955) merely suppresses the warning and is acceptable if you can justify its use. With `<WarningsAsErrors>nullable</WarningsAsErrors>`, all null warnings become errors (15.1.3.3, page 961; the book lists the individual numbers such as `CS8600;CS8602` there).

When the analysis fails to recognize the relationship, attributes can help (15.1.4, page 962): `[NotNullWhen(true)]` describes an `out` parameter that is non-null only if the return value is `true` (the pattern behind `TryParse`); `[NotNullIfNotNull("s")]` specifies that the return value is non-null if the argument `s` is non-null. In addition, there are the operators (15.1.5, page 968): `?.` and `?[ ]` short-circuit on `null`, `??` supplies a fallback value, and `??=` assigns only if the left-hand side is null. New in C# 14 is the **null-conditional assignment** `k?.Alter = 5;`: the assignment and the right-hand side are executed only if `k` is not null (page 970).

## Pattern Matching (15.2, pages 971–987)

Patterns describe the shape of a value and appear after `is` and in `switch` expressions. There are **constant patterns** (`null`, `0`, `"DE"`), **type and declaration patterns** (`string s`, 15.2.3), **relational patterns** (`< 13`, `>= 18`, 15.2.8), and the combinators `and`, `or`, `not` (15.2.9); `not` binds more strongly than `and`, and `and` more strongly than `or`. **Property patterns** (`{ Elektro: true }`, 15.2.4) check properties and are null-safe; extended property patterns are written as `{ Halter.Land: "DE" }`. The **`var` pattern** (15.2.5) captures a partial value in a variable, **positional patterns** (15.2.7) use `Deconstruct` (every record with positional properties has one), **tuple patterns** (15.2.6) evaluate several values at once, and **list patterns** (15.2.10, page 985) describe arrays and lists (`[1, .., 9]`, `[var kopf, .. var rest]`). With `when`, you attach an arbitrary condition to an arm. In `switch` expressions, the order decides: The first matching arm wins; the compiler rejects an unreachable arm as an error and reports missing cases as a warning.

## ref, Span and Co. (15.3 to 15.6, pages 988–1011)

A `ref` return (15.3, page 988) returns a reference to a storage location instead of a value; `Hoechster(a) = 0;` then writes to the array. `ref readonly` avoids copying large structs. `Span<T>` and `ReadOnlySpan<T>` (15.4, page 991) are windows onto existing memory (array, string, stack): slices do not copy anything, and a single parameter type works for all sources. They are **ref structs** (the book's "Verweisstrukturen", 15.4.2, page 992) and live only on the stack. Since C# 14 (15.4.3, page 994), the implicit conversions from arrays and strings to spans are built into the language, so they also apply to the receiver of extension members (for example in `extension` blocks). An **inline array** (15.5, page 1005) is a struct with exactly one field that `[InlineArray(n)]` repeats n times inside the struct: a fixed-size array without an array object of its own. With **params collections** (the book's "Serienparameter mit Kollektionstyp", 15.6, page 1008), `params` may also have the type `ReadOnlySpan<T>`, `IEnumerable<T>`, or `List<T>`, which replaces many overloads.
